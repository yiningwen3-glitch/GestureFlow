当前 Desktop 使用鼠标侧键触发笔势。在「应用管理 → Windows 桌面 → 笔势触发键」选择侧键 1 或 2，所选侧键也适用于已授权应用和输入测试窗口。以下分阶段内容记录开发当时的功能和验证结果。

## 阶段一 · 已完成

2026-11-19 在 Windows 11 x64 上完成初始工程和验证。

- 创建 `GestureFlow.sln` 和 Core、UI、Profiles、Lab、Desktop、Tests 六个项目。解决方案使用 .NET 10，WPF 项目面向 x64。
- 纯 C# 核心处理 `Press`、`Move`、`Release`、`Cancel`，提供 4 / 8 方向识别，以及 `IGestureInputSource` 和 `IActionExecutor`。
- 全局配置支持自定义显示名称、主键和修饰键集合、逐方向开关及逐应用开关。应用默认禁用，标记存在右键冲突风险时需要单独确认。默认绑定和 JSON 往返校验已实现。
- Lab 使用窗口内左键拖动演示圆盘和候选方向，通过模拟执行器显示快捷键。Desktop 提供独立的 WPF 宿主骨架。

- 窗口内左键拖动与 13 个预置场景共用带时间戳的虚拟输入流程。普通右键点击和长按场景只输出诊断结果。

## 阶段四 · 应用风险与保护策略

2026-11-19 为 Desktop 和 Lab 接入应用风险规则、双重确认与保护判定。

- `AppRiskPolicyService` 使用可维护的进程名和 AUMID 匹配规则，覆盖请求中的设计、编辑、办公、开发、部分远程桌面及部分游戏程序。这些规则用于保守保护。
- 授权依次经过风险确认、准备紧急暂停与异常和切换取消保护、选择触发方式，以及独立的最终确认。最终页面展示目标路径、所选触发、保护和剩余风险。关闭、取消、切换目标或刷新清单会丢弃未完成的操作。
- `ProtectionPolicyService` 区分未匹配、待授权、永久禁用、暂停和允许，只有有效授权且触发相符才允许手势进入后续流程。活动手势在暂停、应用切换、异常输入或授权失效时取消。
- Desktop 使用与可读策略文件独立的 Windows 用户级 DPAPI 授权记录。记录关联应用 ID、路径、触发方式和规则内容。阶段三旧授权、授权字段与记录不一致、风险规则变化或身份匹配失效时均会停用。紧急暂停只影响当前运行，解除授权会移除授权记录。
- Lab 的「应用风险测试」使用同一确认控件与保护判定，授权和规则更新保留在内存中。

## 阶段五 · 真实 Windows 输入与快捷键

2026-11-19 为 Desktop 接入全局监听、真实轮盘和快捷键执行。每次启动的默认状态为关闭。

- `WindowsGestureInputSource` 在专用消息线程安装鼠标钩子，并通过有界队列向 WPF 传输事件。钩子使用提前生成的、带时效的前台权限快照，忽略注入事件并防止重复安装。
- 已授权的组合键、鼠标侧键和纯右键触发共享同一识别与命令匹配逻辑。复用 `RadialWheel`，按触发显示器缩放和限制显示位置。识别原点始终是实际按下位置。
- `WindowsActionExecutor` 在调用 `SendInput` 前核对前台、焦点、授权和物理按键。保留已经按住的所需修饰键，冲突时短暂等待，发送失败时报告结果并尝试释放本次部分发送的按键。
- Desktop 支持独立输入测试窗口、托盘控制、可选暂停热键、应用撤权和一键关闭全局监听。Lab 继续独立运行，并共用纯识别逻辑。

### 右键兼容边界

- 纯右键模式仅对短时且移动不超过 4 个屏幕像素的点击尝试补发，条件包括权限仍有效、光标仍在原目标窗口、焦点未变且没有修饰键冲突。长按、右键拖放、双击间隔和依赖原始按下的行为可能改变。
- Alt 组合可能激活应用菜单，侧键可能占用原生前进或后退键功能。窗口或键盘焦点缺失时，触发不生效。

## 阶段六 · 稳定性与 MVP 预览

2026-11-20 为 Windows 11 x64 准备 `0.1.0-preview.1` 自包含便携包，内含 Desktop 与独立 Lab。

- Desktop 与 Lab 分别单实例运行。正常关闭和会话退出释放监听、热键、轮盘、托盘和定时器。
