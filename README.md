# GestureFlow

GestureFlow 是面向 Windows 11 x64 的圆形鼠标手势工具。本仓库包含 .NET 10 手势核心、独立 WPF 模拟器，以及用于发现和管理真实应用的桌面程序。

## 初版预览 0.1.0-preview.1

这是 GestureFlow 的首个预览版本。可从 GitHub Releases 下载 Windows 11 x64 安装包，安装包包含 Desktop、Lab 和 .NET 运行时。欢迎在 Issues 报告问题。

### 便携版

将 ZIP 完整解压到有写入权限的位置，双击 `Desktop\GestureFlow.Desktop.exe`。也可运行 `Lab\GestureFlow.Lab.exe` 单独打开模拟器。此预览包未签名，已包含 Windows x64 .NET 运行时。程序默认不开机启动。Desktop 与 Lab 可同时运行，各自最多打开一个实例。

可在 Desktop 托盘菜单点「退出」。使用新版设置登记过开机启动时，请在删除解压目录前关闭该选项。如曾创建开始菜单快捷方式，可删除当前用户「程序」目录里的 `GestureFlow\GestureFlow.lnk`。若希望同时清除应用授权、手动关联和偏好，可再删除 `%LOCALAPPDATA%\GestureFlow`。用户自行导出的配置和 Lab 用例保存在选定位置。

从源码发布可运行 `pwsh -File .\scripts\Publish-Portable.ps1`，ZIP 和 SHA-256 文件输出到 `artifacts`。详细行为和现场验证范围见 [兼容性说明](docs/COMPATIBILITY.md) 和 [开发进度](docs/PROGRESS.md)。

## 管理真实应用

在仓库根目录运行以下命令。

```powershell
dotnet build GestureFlow.sln -c Release
dotnet run --project .\GestureFlow.Desktop -c Release --no-build
```

桌面主窗口默认打开「首页」，左侧导航切换页面。在「设置」可选择跟随系统、浅色或深色，选择会保存在本机。从「应用管理」查看应用并启用侧键笔势，从「设置 → 帮助与工具」打开独立 Lab。「使用帮助」和「关于软件」可离线查阅。源文档包括 [使用指南](docs/USER_GUIDE.md)、[安全说明](docs/SAFETY.md)、[隐私声明](docs/PRIVACY.md)、[常见问题](docs/FAQ.md) 和 [第三方组件声明](docs/THIRD_PARTY.md)。

首次运行时会显示可跳过的引导。首次关闭时可选择隐藏到托盘或退出软件，之后可在「设置」更改。在「设置」选择「添加到开始菜单」后，可搜索 GestureFlow 来启动。重复启动会唤回已有主窗口。

「设置」支持为当前用户登记登录启动、调整轮盘灵敏度，以及备份和恢复已保存的配置。登录启动会打开主窗口，全局输入保持关闭。恢复备份也会关闭输入监听，真实应用授权仍在「应用管理」中单独管理。

在「设置 → 悬浮控制岛」或托盘菜单显示悬浮岛。点击胶囊查看前台应用、选用专属或通用方案，以及暂停或恢复已启用的笔势。拖动左侧把手可保存位置。设置页可调整置顶、不透明度、默认折叠及自动收起。

「关于软件」从程序集读取版本号。维护者可在 `Directory.Build.props` 中设置 `GestureFlowDeveloper` 和 `GestureFlowDeveloperContact`，也可在构建时通过同名 MSBuild 属性传入。如果提供了项目根目录的 `LICENSE`，构建会将其嵌入关于页。

Desktop 从当前用户与系统的 32/64 位安装注册表、开始菜单、当前用户的 MSIX/Appx 清单和具有窗口的运行进程发现应用。可按名称或启用状态筛选，查看应用详情，或选择已有的 `.exe` 添加便携程序。身份待关联的安装或快捷方式记录可以显式关联到可执行文件。应用来源、访问权限和安装清单的完整性会影响发现结果。

在应用详情核对程序路径，点击「启用笔势」。

应用策略保存在 `%LOCALAPPDATA%\GestureFlow\application-policies.json`，与应用身份、路径和安装标识关联的启用记录单独由 Windows 用户级数据保护保存。首页可查看当前或最近前台应用及其生效方案。

## 使用真实鼠标手势

Desktop 启动后，Windows 桌面默认使用通用方案。按住所选鼠标侧键并向目标方向拖动，松开执行。要在应用中使用，在「应用管理」启用笔势后打开全局输入。「应用管理」列出个人和公共桌面上的应用，以及本机安装的 Word、Excel 等 Microsoft Office 应用。

- Desktop 的「笔势 → 更多方案」可为通用范围和每个应用分别新建、复制、编辑、导入、导出与选用方案。直接编辑当前轮盘，保存时会为系统默认配置创建并启用自定义方案。每套方案可切换 4 / 8 方向，并设置各方向的名称和快捷键。旧版共享 JSON 和 Lab 导出的配置可通过「导入」加载。
- 前台应用启用笔势后，依次使用该应用选用的专属方案、当前通用方案、系统默认方案。手势开始后固定目标和配置，切换或失去目标时取消。打开主窗口后，可从首页继续管理最近前台应用的方案。
- 默认紧急暂停热键为 Ctrl + Shift + F10。监听关闭时可在 Desktop 选择其他组合。托盘可暂停、恢复或关闭手势监听。应用详情中的「停用笔势」会停用该应用的侧键手势。
- 「设置」中的「鼠标侧键」可全局切换鼠标侧键 1 或 2。右键继续由系统和应用处理。点「编辑…」可选择「同时按」或「依次按」。例如依次填写 Ctrl+K 和 Ctrl+C 可分两步执行。
- 接管手势及发送前会核对窗口和焦点所属进程的完整性级别。目标级别更高或无法核对时，原生输入保持放行。发送前还会重新核对授权和物理按键状态。
- 已授权软件重新安装、更新或移动后可能需重新授权。缺少安装标识的旧授权需重新确认。配置损坏时使用对应的默认值并保留原文件。若保护数据无法读取，可选择「停用所有应用笔势」重置启用状态。

## 运行模拟器

在 Windows 11 上安装 .NET 10 SDK，然后在仓库根目录运行以下命令。

```powershell
dotnet build GestureFlow.sln
dotnet test GestureFlow.sln
dotnet run --project .\GestureFlow.Lab
```

构建后也可直接运行 `GestureFlow.Lab\bin\Debug\net10.0-windows\GestureFlow.Lab.exe`。

- 在圆盘画布上按住左键并拖动。移动时高亮候选扇区，松开后显示选中的名称和模拟快捷键。回到中心再松开、按 Esc 或失去鼠标捕获均可取消。
- 在「设置」中切换 4 / 8 方向、编辑显示名称、点击每行的快捷键按钮录制组合键，以及保存、加载或恢复配置。只按 Esc 可退出快捷键录制。有效修改立即显示在轮盘中。
- 在「模拟测试」中运行方向、侧键轻点、长按、无效、取消或快速连续操作。四方向模式中的对角测试会按扇区边界规则映射到相邻方向。
- 选择「开始录制」，使用画布或预置按钮输入，再选择「停止录制」。可将用例保存为 JSON、重新打开和回放。用例保存当时的配置快照与相对时间戳，回放结束后轮盘恢复当前设置。
- 「调试」显示最近的虚拟事件、方向、位移、状态与命令结果。顶部可以切换浅色和深色主题，也可在轮盘上隐藏快捷键。
- 「虚拟应用」可切换 SolidWorks、Photoshop、Word、浏览器和未知应用，模拟启用、停用、暂停和取消。虚拟应用的启用状态保存在 Lab 内存。
- 同页可重新加载 Desktop 已保存的方案，为虚拟应用切换通用和专属方案，查看生效方案并模拟执行指定方向。切换结果只保存在 Lab 内存。
- 「悬浮岛」模拟 Windows 桌面、SolidWorks、VS Code 和 Photoshop 的前台切换。显示悬浮岛后可切换方案、暂停或恢复，并预览向上手势。

Lab 的模拟执行器只更新窗口内的预览和调试记录。系统右键继续由当前应用处理。

## 工程结构

| 项目 | 职责 |
| --- | --- |
| GestureFlow.Core | 纯 C# 状态机、方向识别、结构化快捷键及输入、执行接口。 |
| GestureFlow.Profiles | 方案管理与解析、共享绑定编辑、历史 JSON 兼容与校验。 |
| GestureFlow.UI | 可复用的 WPF 轮盘、窗口内左键输入适配与快捷键录制映射。 |
| GestureFlow.Lab | 独立模拟器、设置界面、模拟执行器、场景与录制回放。 |
| GestureFlow.Desktop | 真实应用发现、授权管理、前台观察、Win32 输入、快捷键执行和托盘。 |
| GestureFlow.Tests | 核心、配置、应用发现和持久化测试，以及 Lab 的 WPF 集成测试。 |

## 手势与默认绑定

识别使用以按下点为原点的二维位移，屏幕 Y 轴向下。4 方向使用 90° 扇区，8 方向使用 45° 扇区，扇区平分边界顺时针归入下一扇区。默认中心半径为 69 DIP，额外预留 2 DIP 边界容差。Desktop 可在设置中改用 57 或 81 DIP 的中心半径。松开位置决定结果，回到阈值以内或取消时丢弃手势。

| 方向 | 默认动作 | 快捷键 | 可用模式 |
| --- | --- | --- | --- |
| 北 | 复制 | Ctrl+C | 4、8 |
| 东 | 粘贴 | Ctrl+V | 4、8 |
| 南 | 撤销 | Ctrl+Z | 4、8 |
| 西 | 剪切 | Ctrl+X | 4、8 |
| 东北 | 重做 | Ctrl+Y | 8 |
| 东南 | 全选 | Ctrl+A | 8 |
| 西南 | 查找 | Ctrl+F | 8 |
| 西北 | 保存 | Ctrl+S | 8 |

## 配置模型

使用 `DefaultGestureProfiles.Create` 创建某种方向模式的默认绑定。每套方案包含当前模式中所有方向的绑定，可通过 `enabled` 禁用单个方向。下面的 JSON 片段展示了一条自定义绑定。

```json
{
  "direction": "North",
  "displayName": "自定义动作",
  "shortcut": {
    "key": "F12",
    "modifiers": ["Control", "Shift"]
  },
  "enabled": true
}
```

`GestureProfileManager` 在 `%LOCALAPPDATA%\GestureFlow\gesture-profiles.json` 保存方案与选用项。首次迁移会备份旧配置，再保留原方向、显示名称和快捷键。应用授权使用独立的应用策略和保护记录。恢复步骤见 [使用指南](docs/USER_GUIDE.md)。

Lab 切换方向数时会在当前会话保留已编辑的方向绑定。配置文件保存当前模式的方向，加载四方向文件后新增的对角方向使用默认绑定。只按修饰键、未支持的主键和空白显示名称均无法写入配置。由 Windows 拦截的系统级组合键可能无法在窗口内录制。

开发进度和后续工作见 [docs/PROGRESS.md](docs/PROGRESS.md)。
